# dviewer

[한국어](README.md) | [English](README.en.md)

마크다운·JSON·JSONC·JSONL·YAML·TOML·XML·CSV·TSV·텍스트/로그·SQLite·Excel·Parquet·ZIP을 읽기 위한 데스크톱 뷰어. Tauri v2 + Rust 백엔드 + Svelte 5 프론트엔드. 인터페이스는 한국어·영어·일본어·중국어(간체)를 지원합니다.

열네 가지 형식이지만 읽는 방식은 **다섯**입니다. 형식마다 화면을 만들면 열네 벌을 따로 손봐야 하고, 그중 열셋은 늘 뒤처집니다.

| 보기 | 형식 | 하는 일 |
| --- | --- | --- |
| 글 | 마크다운 | GitHub 수준 렌더링(표·체크박스·각주·알림 블록), 코드 구문 강조, Mermaid, KaTeX. 원문/렌더 토글 |
| 트리 | JSON · JSONC · YAML · TOML · XML | 접기/펼치기, 키·값·경로 검색, 깊이별 가이드선, 키/값 표, 경로 팝오버, 우클릭 복사 |
| 표 | CSV · TSV · 텍스트/로그 · JSONL/NDJSON | 고정된 머리글과 행 번호, 끌어서 조절하는 열 너비, 칸 단위 검색과 복사. **로그는 앞 필드를 알아보고 열로 나눕니다** — 시각·수준·출처·메시지, 그리고 원하면 `키=값`까지 |
| 컬렉션 | SQLite · Excel(xlsx) · Parquet | 한 파일에 든 여럿 중 하나를 골라 같은 격자로 봅니다. SQLite 는 읽기 전용 연결과 DDL 보기, xlsx 는 시트 선택과 수식 보기, Parquet 은 스키마 보기 |
| 압축 | ZIP | 안에 든 문서의 목록. 고르면 **위의 네 가지 중 제 것으로** 새 탭에 열립니다 — 화면에서 끝나지 않고 다른 문서로 이어지는 유일한 보기 |

- 500MB급 JSON·CSV와 200MB급 로그를 통째로 메모리에 올리지 않고 다룹니다. 자세한 수치는 [검증과 성능](doc/verification.md)에 있습니다.
- 파일 선택, 드래그 앤 드롭, URL, 붙여넣기 네 경로로 열 수 있고 탭으로 여러 문서를 동시에 봅니다.
- 형식은 확장자로 정하고(판별되지 않으면 텍스트), 문자 인코딩(UTF-8 · CP949/EUC-KR · UTF-16 등)은 내용으로 판별합니다. 둘 다 도구 모음에서 언제든 바꿀 수 있습니다.
- **로그는 열로 나뉩니다.** 앞머리의 시각·수준·`[출처]` 를 알아보고 나머지는 메시지 한 열에 둡니다. 스택 트레이스처럼 시각으로 시작하지 않는 줄은 앞 레코드에 이어 붙습니다. `키=값` 쌍은 도구 모음에서 펼칠 수 있고, 언제든 한 줄짜리로 되돌릴 수 있습니다. ERROR·WARN 은 레벨 칸에만 은은한 색이 붙습니다. 추론이 확실하지 않으면 나누지 않습니다.
- **JSONL 은 표입니다.** 한 줄이 한 행, 키가 열입니다. 열은 앞부분 표본에서 알아내고, 없는 키는 빈 칸으로 둡니다 — 줄이 객체가 아니면 나누지 않습니다. 언제든 한 열짜리 원본 줄로 되돌릴 수 있고, 형식을 JSON 으로 바꾸면 같은 파일이 트리로 열립니다.
- **주석이 있는 JSON 은 JSONC 로 읽습니다.** `.jsonc` 는 `//`·`/* */` 주석과 후행 쉼표를 지나갑니다. `.json` 은 그대로 엄격합니다 — 대신 엄격한 읽기가 멈춘 자리가 JSONC 였다면 지나갔을 자리이면, 오류가 그 전환을 알려 줍니다.
- **JSONC 의 주석이 값 옆에 남습니다.** 값 **위**에 쓰인 설명과 값 **뒤**에 같은 줄로 쓰인 덧말이 그 행 끝에 흐리게 붙고, 고르면 키/값 표에 각각 전문이 나옵니다 — 저자가 그 자리에 쓴 이유가 거기서 읽히라는 것이니까요. 덧말은 그 줄에서 끝난 것에 붙으므로 `} // 여기까지` 는 그 블록의 말이 됩니다.
- **JSONPath 로 노드를 고를 수 있습니다** (트리 뷰). `$.items[0].name` · `$..title` 처럼 자리를 고르고, `$..book[?@.price < 10]` 처럼 **값으로 걸러**낼 수도 있습니다 — 슬라이스(`$.items[1:3]`)·합집합(`$.items[0,-1]`)·뒤에서 세는 인덱스(`$.items[-1]`)까지 RFC 9535 의 선택자 전부입니다. 글자를 찾는 것이 아니라 자리를 고르는 것이라, 3,840만 노드 파일에서 `$..notes` 가 0.06초입니다. 기존 경로 부분 일치 검색은 그대로 있습니다.
- **정규식으로 찾을 수 있습니다.** 검색창의 `.*` 를 켜면 질의를 정규식으로 읽습니다 — 트리에서는 키 하나·값 하나, 격자에서는 칸 하나 안에서 맞추므로 `^\d+$` 가 뜻대로 동작합니다. 끄면 지금까지와 똑같은 리터럴 검색입니다.
- **Parquet 은 여는 시간이 파일 크기를 따라가지 않습니다.** 끝에 붙은 색인만 읽고, 화면이 닿는 행 그룹만 풀어서 보여줍니다 — 52MB 0.19ms, 311MB 0.61ms 로, 자라는 것은 행 그룹 수뿐입니다. 그래서 다른 형식들이 가진 전체 상한이 없습니다.
- **Excel 통합 문서를 엽니다.** 시트를 골라 표로 봅니다. 열 이름은 `A`·`B`·`AA`, 1행은 1행 — 원본과 대조할 때 좌표가 어긋나지 않게. 날짜는 ISO 8601 로, 수식은 토글로 값 대신 볼 수 있습니다. 변환해서 읽으므로 64MB 상한이 있습니다.
- **열네 형식 전부가 압축 파일 안에서도, 주소로도 열립니다.** Excel · Parquet · SQLite 까지 모두 바이트를 받는 리더로 읽으므로 파일일 필요가 없습니다. 압축에서 꺼낸 데이터베이스는 파일을 질의하는 대신 그 **이미지를 제자리에서** 읽습니다 — 사본을 만들지 않고, 그래서 압축 항목의 512MB 상한이 그대로 상한입니다. Excel 의 64MB 도 그대로입니다.
- **SQLite 는 질의로 읽습니다.** 바이트를 훑지 않는 첫 형식입니다. 파일을 읽기 전용으로 열어 표와 뷰의 목록을 보여주고, 고른 것의 행을 CSV 와 **같은 격자**로 그립니다. 1,024행마다 위치를 적어 두므로 300만 번째 행으로도 곧장 갑니다.
- **압축 파일은 열어서 고릅니다.** `.zip` 을 열면 안에 든 것의 목록이 나오고, 하나를 고르면 새 탭에서 제 형식으로 열립니다 — 열네 번째 형식이라기보다 앞의 열세 개의 곱셈입니다. 여는 값은 파일 끝의 목차뿐이라 1GB 짜리도 0.1초입니다(푸는 것은 고른 항목 하나뿐). 안에 든 문서가 하나뿐이면 목록을 건너뛰고 바로 그것을 엽니다. **이름이 UTF-8 이 아닌 압축 파일도 읽습니다** — 압축 파일 하나의 이름을 전부 모아 한 번에 인코딩을 추측하고, 추측일 때는 상태줄이 그렇게 말합니다.
- **gzip 파일은 그냥 열면 됩니다.** `access.log.gz` 를 열면 압축을 풀어 안쪽 이름(`access.log`)으로 형식을 정합니다. 원문 보기도 풀린 내용을 보여줍니다.
- 다크/라이트(기본 자동), 인터페이스 배율, 인터페이스·본문 글자 크기, 시스템 글꼴 목록에서 고르는 본문·코드 글꼴을 지정할 수 있습니다.

## 필요 환경

- Node.js 20 이상 (개발 기준 24), npm
- Rust 1.88 이상 — calamine이 요구하는 하한입니다 (개발 기준 1.94)
- [Tauri v2 사전 요구사항](https://v2.tauri.app/start/prerequisites/) — Windows는 WebView2와 MSVC 빌드 도구, Linux는 `webkit2gtk`

## 실행

```bash
npm install && npm run tauri dev
```

배포본을 만들려면:

```bash
npm run tauri build
```

`src-tauri/target/release/` 에 실행 파일이, `bundle/msi`·`bundle/nsis` 에 설치본이 생성됩니다.

## 명령줄

```bash
dviewer report.md                      # 위치 인자
dviewer --open="C:/데이터/큰파일.json"
dviewer --open-url=https://example.com/data.json
dviewer --new --open=a.csv             # 탭이 아니라 새 창으로
```

두 번째 실행은 창을 만들지 않고 이미 돌고 있는 프로세스의 **현재 창에 탭으로** 붙습니다. `--new` 를 주면 그때만 창을 하나 더 만듭니다. 동작 원리는 [설계와 구조](doc/architecture.md#명령줄-그리고-이미-열려-있는-창)에 있습니다.

## 알려진 한계

- JSON 파일은 4GB까지입니다 (오프셋이 `u32`).
- 정규식은 **하나의 값 안에서** 맞춥니다 — 트리에서는 키 하나·값 하나, 격자에서는 칸 하나. 여러 노드나 여러 칸에 걸친 매치는 없습니다. `^`·`$` 가 뜻을 가지려면 그래야 합니다.
- 정규식 검색은 리터럴보다 느립니다. 값을 하나씩 보기 때문이고, 300MB CSV 에서 1.5초쯤입니다(리터럴은 0.05초). 도중에 멈출 수 있습니다.
- 붙지 않는 주석이 셋 있습니다: 여는 괄호 바로 뒤(`[ // 이 배열은`), 키와 값 사이(`"k": /* x */ 1`), 그리고 닫는 괄호 앞 자기 줄. 앞의 둘은 아직 끝난 값이 없고, 셋째는 뒤따르는 것을 설명하지도 않으면서 앞 블록의 설명으로 보기에는 저자의 뜻이 갈립니다 — 엉뚱한 것에 붙이느니 보여주지 않습니다.
- JSONPath 는 **선택자도 함수도 RFC 9535 그대로**입니다 — 선택자 전부에 더해 `length()` · `count()` · `match()` · `search()` · `value()` 를 필터 안에서 씁니다. 타입은 **쓰는 동안** 봅니다: `length(@.*)` 처럼 한 노드로 좁혀지지 않는 것에 길이를 물으면 문서를 열기도 전에 거절당합니다. 남은 것은 객체·배열을 통째로 비교하는 것(`?@.a == @.b` 에서 양쪽이 객체인 경우) 하나이고, 쓰면 무엇이 없는지 이름을 대는 오류가 납니다. 합집합 결과는 문서 순서이고 중복이 없습니다 — RFC 는 `[0,0]` 에 같은 노드를 두 번 주지만, 뷰어에서 한 노드를 두 번 하이라이트하는 것은 뜻이 없습니다.
- JSONPath 의 뒤쪽 인덱스와 슬라이스는 **앞에서부터 걷습니다.** 자식은 색인에서 이어 붙어 있어 n번째에 닿으려면 그 앞을 밟아야 하므로, `[-1]` 이나 `[1000000:]` 은 그 행까지 스크롤하는 것과 같은 값이 듭니다 — 240만 항목 배열에서 14ms 입니다. 슬라이스는 몇 개를 고르든 그 걷기를 한 번만 하고, 합집합은 조각마다 한 번씩 합니다.
- JSONPath 는 XML 에는 없습니다. XML 경로는 XPath 모양이라 표현식의 뜻이 달라집니다.
- 리터럴 검색의 대소문자 무시는 ASCII 범위에서만 동작합니다. 정규식 쪽은 크레이트가 유니코드까지 봅니다.
- 마크다운 렌더링은 16MB까지입니다. 그보다 큰 파일은 열리지 않습니다.
- 펼침 깊이 프리셋은 9까지이며 기본값도 9입니다. 그보다 깊은 단계는 개별 노드를 펼쳐서 봅니다.
- 파일을 mmap 하므로, 열어 둔 파일이 밖에서 바뀌면 다시 열어야 합니다. 내용만 바뀐 경우는 읽던 값이 섞여 보이는 정도이지만, **파일이 잘리면 Linux·macOS 에서는 프로세스가 그대로 죽습니다**(SIGBUS). Windows 는 매핑이 열려 있는 파일의 축소를 OS 가 거부하므로 해당하지 않습니다.
- 마크다운의 원격 이미지를 허용합니다. `img-src` 에 `https:` 가 들어 있어 배지 같은 것이 그대로 보이는 대신, 문서를 열었다는 사실이 그 이미지를 주는 서버에 남습니다. 문서가 웹에서 보이는 그대로 보여야 한다고 판단한 결과입니다.
- SQLite 의 뷰와 WITHOUT ROWID 테이블은 rowid 가 없어 행 위치를 미리 적어 둘 수 없습니다. 앞쪽은 똑같이 빠르지만 뒤쪽으로 갈수록 한 화면을 얻는 데 오래 걸립니다. 일반 테이블은 크기와 무관하게 일정합니다.
- SQLite 데이터베이스는 훑기가 500만 행에서 멈춥니다. 그보다 큰 테이블은 앞 500만 행만 보이고 상태줄이 그렇게 알립니다.
- Parquet 의 행 그룹 하나가 400만 행을 넘으면 열지 않습니다. 행 그룹은 절반만 풀 수 없는 단위라, 그보다 크면 처음 닿는 순간 창이 몇 초씩 멈춥니다. 보통 10만~100만 행으로 쓰이므로 실제로 걸리는 파일은 드뭅니다.
- Excel 은 통합 문서를 메모리로 변환해 읽으므로 64MB 까지입니다. 값이 파일보다 커집니다 — 실측으로 9.7MB 파일이 51MB 가 됩니다. 시트의 수식 칸은 Excel 이 **마지막으로 계산해 둔 값**을 보여줍니다 — 다시 계산하지 않고 저장된 파일이라면 그 값이 낡았을 수 있습니다. 셀의 표시 서식은 재현하지 않습니다(날짜는 ISO 8601). `.xls`(옛 이진 형식)는 읽지 않습니다.
- SQLite 는 읽기 전용으로만 엽니다. **파일로 열 때**, 쓰다 만 트랜잭션이 남아 롤백 저널(`-journal`)이 붙어 있는 데이터베이스는, 읽기 전용으로는 그 롤백을 수행할 수 없어 첫 질의에서 오류가 납니다 — 그 데이터베이스를 만든 프로그램이 한 번 열어 정리한 뒤에 봐야 합니다. 압축 파일 안이나 주소에서 온 데이터베이스에는 곁파일 자체가 없으므로 마지막 체크포인트 상태로 보입니다 — 쓰기 앞서 기록하는 로그(WAL)가 있었더라도 그것은 압축되지 않았을 테니까요.
- 압축 파일은 zip 만 읽습니다. `tar.gz` 는 목차가 없어 목록을 만드는 일이 곧 전체를 푸는 일이라, 비용 모델이 다릅니다.
- 압축 파일 안의 항목은 512MB까지 풀립니다. 파일이 적어 둔 크기가 아니라 **실제로 나온 양**을 봅니다 — 적어 둔 숫자는 압축 파일을 만든 쪽이 마음대로 쓸 수 있으니까요.
- 암호가 걸린 항목은 목록에 자물쇠로 표시하고 열지 않습니다. 암호를 묻지도 풀지도 않습니다.
- 압축 파일 안의 마크다운은 상대 경로 이미지가 보이지 않습니다. 그 이미지가 있는 곳은 압축 파일 안이고, 웹뷰가 닿을 수 있는 자리가 아닙니다.
- 압축 파일은 세 겹까지 들어갑니다 (`a.zip → b.zip → c.zip` 안의 문서까지). 한 겹 들어갈 때마다 그 겹이 통째로 메모리에 남습니다.
- 같은 이름이 두 번 든 압축 파일은 마지막 항목만 보입니다. 목차를 이름으로 찾는 구조라 가려진 쪽에는 닿을 길이 없고, 두 행을 그리고 같은 바이트를 여는 것은 가진 것을 속이는 일이라 하나만 그립니다.
- 압축 파일의 항목은 최근 문서에 남지 않습니다. 최근 목록은 파일 경로로 다시 여는데, 항목에는 그런 경로가 없습니다.
- 압축 파일 안 이름의 인코딩은 추측입니다. 틀려도 여는 데에는 지장이 없습니다 — 항목은 이름이 아니라 목차의 번호로 찾습니다.
- 문서 편집·저장 기능은 없습니다. 읽기 전용 뷰어입니다.
