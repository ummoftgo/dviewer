# dviewer

마크다운과 JSON을 읽기 위한 데스크톱 뷰어. Tauri v2 + Rust 백엔드 + Svelte 5 프론트엔드.

- **마크다운** — GitHub 수준 렌더링(표·체크박스·각주·알림 블록), 코드 구문 강조, Mermaid 다이어그램, KaTeX 수식. 원문/렌더 토글.
- **JSON** — 500MB 이상도 다루는 접기/펼치기 트리와 키·값·경로 검색. 깊이별 세로 가이드라인, 선택한 항목의 키/값 표, 키 호버 시 전체 경로 팝오버, 우클릭으로 경로/키/값 복사.
- 파일 선택, 드래그 앤 드롭, URL, 붙여넣기 네 경로로 열 수 있고 탭으로 여러 문서를 동시에 봅니다.
- 다크/라이트(기본 자동), 인터페이스 배율, 인터페이스·본문 글자 크기, 시스템 글꼴 목록에서 고르는 본문·코드 글꼴을 지정할 수 있습니다.

## 필요 환경

- Node.js 20 이상 (개발 기준 24), npm
- Rust 1.85 이상 — comrak과 ureq이 요구하는 하한입니다 (개발 기준 1.94)
- [Tauri v2 사전 요구사항](https://v2.tauri.app/start/prerequisites/) — Windows는 WebView2와 MSVC 빌드 도구, Linux는 `webkit2gtk`

## 실행

```bash
npm install && npm run tauri dev
```

배포본을 만들려면:

```bash
npm run tauri build
```

`src-tauri/target/release/` 에 실행 파일이, `bundle/msi`·`bundle/nsis` 에 설치본이 생성됩니다.


## 설계 요약

무거운 작업은 전부 Rust에 있고, 프론트엔드는 화면에 보이는 만큼만 그립니다.

### JSON: 왜 이렇게까지 하는가

500MB JSON을 `serde_json::Value` 로 파싱하면 힙이 수 GB로 부풉니다. 대신:

1. **바이트 스캐너** (`src-tauri/src/json/scanner.rs`) 가 mmap된 원본을 한 번만 훑으며 노드당 36바이트짜리 평면 인덱스를 만듭니다. 노드는 DFS 선행순서로 나열되므로 **노드 id 순서 = 바이트 순서**이고, 이후 모든 단계가 이 불변식 위에 서 있습니다.
2. **가시성 관리** (`json/index.rs`) 는 노드당 1비트 + 4096노드 단위 블록 카운트입니다. "N번째 보이는 행이 어느 노드인가"는 블록 카운터를 훑고 블록 안에서 popcount 하면 끝이고, 접기는 비트 범위를 지우고 영향받은 블록만 다시 세면 됩니다. Fenwick 트리는 조회가 빠른 대신 접기가 비싸고, 단순 플래그 배열은 그 반대입니다.
3. **뷰포트 조회** (`json/mod.rs`) 는 보이는 100여 행만 반환하고 값은 500자에서 자릅니다. 파일 크기와 무관하게 IPC 페이로드는 수 KB입니다.
4. **검색** (`json/search.rs`) 은 원본 바이트를 aho-corasick으로 훑고, `val_start` 가 노드 순서로 단조 증가한다는 점을 이용해 이진 탐색으로 매치를 노드에 되돌립니다.

**경로 검색**은 다릅니다. 경로는 파일 어디에도 없고 트리에서 파생되는 값이라 바이트 스캔으로 찾을 수 없습니다. 대신 선행순서로 나열된 노드 배열을 훑으며 버퍼 하나를 재사용합니다 — 부모 길이까지 자르고 자기 세그먼트만 덧붙이는 식이라, 노드마다 문자열을 만들지 않습니다. 두 가지 성질이 비용을 낮춥니다: 조상이 이미 일치하면 그 하위 전체가 일치하므로 다시 찾지 않고, 아니라면 접두사는 불일치가 확정이므로 **새로 붙인 꼬리만** 훑으면 됩니다. 덕분에 노드당 비용이 경로 깊이가 아니라 검색어 길이에 비례합니다.

인덱싱과 검색은 백그라운드 스레드에서 돌고 진행률·결과를 이벤트로 흘려보냅니다. 탭을 닫으면 취소됩니다.

### 트리 읽기: 색이 아니라 선

계보를 알려주는 건 **선**입니다. 색은 같은 깊이의 다른 형제 블록에 같은 값을 주므로 "몇 층인가"만 답할 뿐 "어느 부모에 속하는가"를 답하지 못하고, 키에 색을 입히면 값 타입 색과 경쟁합니다. 그래서 구조는 세로 가이드선이 담당합니다.

그 위에 **깊이별 색조를 보조 단서로** 얹었습니다 (`--guide-1` … `--guide-9`, 9단계마다 순환). 가이드는 왼쪽 여백의 1px 선이라 값 색과 겹칠 일이 없고, 층수를 세지 않고도 눈으로 가늠하게 해줍니다.

색은 눈대중으로 고르지 않았습니다. 색상환을 9등분(40°)하고 레벨 k에 `((k-1) × 4 mod 9)` 번째 칸을 배정하면 **인접한 모든 쌍이 정확히 160° 떨어집니다** — 9에서 1로 되돌아가는 순환 지점까지 포함해서요. 9주기 순환에서 얻을 수 있는 최대 간격입니다. 여기에 명도를 홀짝으로 번갈아 줘서 이웃한 레벨은 색상과 밝기 두 가지로 갈라지고, 색각 이상에서도 구분됩니다.

선택한 블록의 가이드를 강조할 때는 **그 레벨의 색조를 유지한 채** 본문 색 쪽으로 밀어 넣습니다 (`color-mix(in oklab, var(--guide-color) 78%, var(--text))`). 라이트에서는 어두워지고 다크에서는 밝아지는데, 한 가지 강조색으로 통일해 버리면 독자가 따라가던 단서 자체를 지우게 되기 때문입니다.

행을 선택하면 그 행의 **직속 부모 가이드가 블록 범위만큼 강조**됩니다. 선행순서 나열에서 블록은 연속 구간이므로, 로드된 창에서 선택 지점 위아래로 깊이가 낮아질 때까지 훑으면 형제 그룹의 정확한 범위가 나옵니다 — 백엔드에서 추가 데이터를 받을 필요가 없습니다.

행 미리보기는 항상 **한 줄**입니다. 트리는 행을 고정 높이로 그리고 인덱스로 위치를 잡으므로, 개행이 든 값은 아래 행들 위에 겹쳐 그려집니다(26px 행에 68px 텍스트). 그래서 제어 문자로 디코드되는 이스케이프는 이스케이프 형태로 남깁니다 — `"a\nb"` 는 `a\nb` 로 보입니다. 렌더링 가능하면서 파일에 실제로 적힌 그대로입니다. 스캐너가 관대해서 문자열 안에 진짜 제어 문자가 들어올 수도 있으므로 그것도 같이 처리하고, CSS가 줄바꿈으로 취급하는 U+2028/U+2029 도 포함합니다. 미리보기는 **JSON 문자열 본문 형태**입니다 — 백슬래시와 따옴표도 이스케이프합니다. 안 그러면 `"a\nb"`(개행)와 `"a\\nb"`(백슬래시+n)가 화면에 똑같이 보여 서로 다른 두 값이 구분되지 않고, 어디까지가 이스케이프인지도 알 수 없습니다.

그 덕에 프론트엔드는 백슬래시를 만나면 무조건 이스케이프의 시작으로 읽을 수 있고, 이스케이프 구간에만 별도 색과 옅은 배경 칩을 입힙니다. 색만으로는 부족합니다 — 글자가 앞뒤 단어에 붙어 보이는 걸 실제로 끊어주는 건 칩의 경계입니다.

**복사는 반대 일**입니다. 미리보기는 한 줄이어야 하지만 클립보드는 값 자체를 원하므로, 문자열은 따옴표를 벗기고 이스케이프를 실제 문자로 되돌려 줍니다 — 행에는 `a\nb` 로 보여도 붙여넣으면 진짜 두 줄입니다. 오브젝트·배열은 원본 JSON을 그대로 돌려줍니다. 그쪽은 소스가 곧 값이고, 다른 곳에 붙여넣을 수 있어야 하기 때문입니다.

트리의 행은 뷰포트에 맞춰 자르지 않고 **내용 길이만큼** 늘어납니다. 긴 값은 말줄임표로 끝나는 대신 가로 스크롤로 끝까지 볼 수 있습니다(행 미리보기는 노드당 500자까지 전달됩니다).

옆의 **키/값 표**는 트리가 답하지 않는 질문을 맡습니다. 트리는 "지금 어디인가"를, 표는 "여기에 무엇이 있는가"를 보여줍니다. 컨테이너를 선택하면 그 하위 항목을, 스칼라를 선택하면 그 항목이 놓인 **레벨**(부모의 하위 항목)을 보여줍니다 — 어느 쪽인지는 Rust의 `JsonIndex::table_target` 이 정하므로 프론트엔드는 부모를 알 필요가 없습니다. 표 안의 오브젝트·배열은 값을 한 줄로 적을 수 없으니 `{ … }` / `[ … ]` 로 두고, 누르면 트리에서 그 노드를 클릭한 것과 같이 동작합니다.

패널 너비와 키/값 열의 경계는 모두 끌어서 조절합니다(화살표 키로도 되며 두 번 누르면 기본값). 창을 줄여도 트리 쪽 폭은 확보됩니다. 두 손잡이는 같은 `Splitter` 컴포넌트인데, 측정 방식(패널은 오른쪽 끝에서의 픽셀, 열은 왼쪽에서의 비율)만 콜백으로 주입받습니다.

열 경계는 퍼센트가 아니라 **픽셀 하나**로 계산합니다. 표는 스크롤 영역의 콘텐츠 박스를 채우고 구분선은 패널을 기준으로 놓이는데, 세로 스크롤바가 생기면 그 둘의 폭이 달라져 선이 실제 열 경계에서 어긋나기 때문입니다. 표의 우클릭 메뉴는 트리의 것과 **같은 코드**(`json/actions.ts`)에서 나옵니다 — 두 벌로 두면 언젠가 한쪽이 엉뚱한 것을 복사하게 됩니다. 본문 행은 얼룩말 줄무늬로 구분하고 행 경계선은 두지 않았습니다. 둘 다 넣으면 표가 데이터보다 시끄러워집니다.

경로는 두 경로로 제공합니다. 마우스는 키 호버 팝오버, 키보드는 상태 표시줄의 선택 행 경로 — 호버 전용 정보를 만들지 않기 위해서입니다.

팝오버는 키 **위쪽**에 뜹니다. 아래는 다음에 눈이 갈 행들이 있는 자리라서입니다 (창 상단에 여유가 없으면 아래로 뒤집습니다). 배경은 페이지와 뚜렷이 다른 전용 토큰(`--popover-bg`)을 쓰는데, 라이트에서 흰 패널을 흰 페이지 위에 띄우면 보이지 않고 다크에서도 그냥 또 하나의 패널로 읽히기 때문입니다. 페이지 대비는 라이트 14.6:1, 다크 3.5:1 입니다.

### 여는 동안의 피드백

문서를 여는 일은 디스크를 건드립니다. 그래서 탭은 **백엔드가 답하기 전에** 먼저 나타나고, 파일명과 스피너를 보여준 뒤 내용이 채워집니다. 메타데이터를 기다렸다가 탭을 만들면 그 사이가 완전히 비어 있어 앱이 멈춘 것처럼 보입니다. 같은 이유로 `open_path` 와 `doc_source_text` 는 async 커맨드입니다 — 동기 커맨드는 UI 스레드에서 실행되므로, 콜드 파일이나 네트워크 드라이브에서는 디스크가 답할 때까지 창 전체가 실제로 멈춥니다.

### 크기 조절: 두 개의 독립된 손잡이

**인터페이스 배율**은 글자와 여백을 함께 확대하고, **인터페이스 글자 크기**는 화면 요소의 글자만 바꿉니다. 둘을 진짜로 분리하려면 크롬의 글자 크기가 루트(`rem`)가 아니라 본문 크기를 따라야 해서, 인터페이스의 모든 `font-size` 를 `em` 으로 바꿨습니다. 여백은 `rem` 으로 남겨 배율만 따라갑니다. 여기에 **본문 글자 크기**(렌더된 마크다운과 JSON 트리)가 별도로 있습니다.

글꼴은 `fontdb` 로 시스템에 설치된 목록을 읽어 고릅니다 — 자유 입력은 오타가 조용히 실패하기 때문입니다. 코드 글꼴 목록은 고정폭 계열을 먼저 묶어 보여줍니다.

스캔은 설정 패널을 처음 열 때 백그라운드 스레드에서 한 번만 돕니다. 비용은 표시되는 계열 수가 아니라 **읽어야 하는 얼굴(face) 수**에 비례합니다:

```bash
cd src-tauri && cargo run --release --example fonts
```

이 기계(글꼴 117계열 / 421얼굴)에서 릴리스 **39ms**, 디버그 56ms, 얼굴당 88µs. 얼굴 2,000개짜리 환경이면 약 175ms로 외삽됩니다. 두 번째 호출부터는 캐시되어 0ms입니다.

**보조 글꼴**을 함께 지정하면 `기본, 보조, 기본 스택` 순의 폰트 스택이 만들어지는데, 브라우저는 스택을 **글리프 단위로** 훑으므로 한글이 없는 라틴 전용 글꼴을 골라도 한글만 보조 글꼴이 받습니다.

### 마크다운

`원문 → comrak(GFM) → syntect 구문 강조 → ammonia 정화 → HTML` 까지가 Rust이고, 브라우저가 꼭 필요한 세 가지만 프론트엔드에서 합니다: 상대 이미지 경로를 asset 프로토콜로 바꾸기, Mermaid 렌더, KaTeX 조판 (`src/lib/components/markdown/enhance.ts`).

구문 강조는 인라인 스타일이 아니라 **클래스 기반**이고, 라이트/다크 두 스타일시트를 미리 만들어 둡니다. 그래서 테마를 바꿔도 문서를 다시 렌더링하지 않습니다.

URL과 클립보드로 들어온 문서도 있으므로 ammonia 정화는 선택이 아닙니다. `<script>`·`onerror`·`javascript:` 는 `markdown.rs` 의 테스트로 막혀 있습니다.

### 보안 경계

- 프론트엔드에는 파일시스템 권한이 없습니다 (`src-tauri/capabilities/default.json` 에 `fs:*` 없음). 파일 읽기는 전부 Rust 커맨드를 거칩니다.
- asset 프로토콜 스코프는 비어 있는 채로 시작하고, 문서를 열 때 **그 문서의 디렉터리만** 추가됩니다.
- 외부 링크는 웹뷰에서 이동하지 않고 시스템 브라우저로 넘깁니다.

## 검증

```bash
cd src-tauri && cargo test          # 70개: 스캐너, 가시성, 검색, 표시/복사, 정화
```

성능은 창 없이 직접 잽니다:

```bash
node scripts/gen-fixtures.mjs --huge
cd src-tauri && cargo run --release --example scan -- ../fixtures/huge.json "needle:"
```

이 저장소를 만든 기계(Windows 11)에서 526MB / 3,840만 노드 기준:

| 항목 | 값 |
|---|---|
| 인덱싱 | 1.26초 (418 MB/s) |
| 인덱스 메모리 | 1.3 GB |
| 전체 펼치기 | 29ms → 3,840만 행 |
| 중간 100행 조회 | 0.0ms |
| 본문 검색 (48,000건) | 1.16초 |
| 경로 검색 (3,840만 노드 순회) | 1.68초 |

인덱스 메모리는 노드 수에 비례합니다(노드당 36바이트). 위 픽스처는 값이 잘게 쪼개져 있어 바이트당 노드 밀도가 높은 최악에 가까운 경우입니다.

렌더링 결과를 눈으로 확인하려면:

```bash
cd src-tauri && cargo run --release --example render -- ../fixtures/sample.md out.html
```

`fixtures/` 에는 `small.json`, `wide.json`(루트 배열 100만), `deep.json`(깊이 500), `stream.jsonl`, `broken.json`(중간 절단), 그리고 렌더링 기능을 한 번에 훑는 `sample.md` 가 있습니다.

## CI / 배포

`.github/workflows/build.yml` 하나가 두 가지 일을 합니다.

| 계기 | 하는 일 |
| --- | --- |
| main 푸시 · PR | 테스트만. Linux·macOS·Windows 세 러너에서 `cargo test`, 타입 체크와 프런트엔드 빌드는 Linux에서 한 번 |
| `v*` 태그 | 테스트 후 세 OS 번들을 만들고 **초안 릴리스**에 붙임 |
| 수동 실행 | 기본은 테스트만. `bundle` 입력을 켜면 릴리스 없이 번들만 만들어 아티팩트로 남김 |

main에서 번들을 만들지 않는 대신 테스트는 세 OS 모두에서 돌립니다. Linux에서만 돌리면 Windows나 macOS에서만 깨지는 변경을 태그를 밀 때까지 모릅니다.

### 산출물

OS마다 설치본과 포터블을 함께 냅니다.

| | 설치본 | 포터블 |
| --- | --- | --- |
| Windows x64 | `_setup.exe` (NSIS), `.msi` | `_portable.zip` — 푼 뒤 `dviewer.exe` 실행 |
| macOS universal | `.dmg` | `_portable.zip` — 푼 뒤 `dviewer.app` 실행 |
| Linux x86_64 | `.deb`, `.rpm` | `.AppImage` — `chmod +x` 후 실행 |

macOS는 `universal-apple-darwin` 하나로 Apple Silicon과 Intel을 모두 덮습니다. Linux는 `ubuntu-22.04` 에서 빌드합니다 — glibc는 위로만 호환되므로 빌드에 쓴 배포판이 실행 가능한 가장 낮은 배포판을 정합니다.

포터블 압축은 OS마다 다른 도구를 씁니다. macOS는 `zip` 이 아니라 `ditto` 인데, `.app` 은 심볼릭 링크와 실행 권한을 가진 디렉터리라 일반 zip으로 감으면 푼 쪽이 실행되지 않습니다. Windows 포터블은 파일 하나입니다 — 프런트엔드가 실행 파일 안에 들어가 있고 옆에 딸려 나가는 것이 없습니다.

포터블은 "설치가 필요 없다"는 뜻이지 "흔적을 남기지 않는다"는 뜻은 아닙니다. 설정은 `tauri-plugin-store` 를 통해 OS의 설정 디렉터리에 그대로 저장됩니다.

### 제약

**서명은 하지 않습니다.** macOS는 처음 열 때 우클릭 → 열기, Windows는 SmartScreen에서 추가 정보 → 실행이 필요합니다. macOS를 제대로 배포하려면 Apple Developer ID를 받아 `APPLE_CERTIFICATE`·`APPLE_SIGNING_IDENTITY`·`APPLE_ID`·`APPLE_PASSWORD`·`APPLE_TEAM_ID` 시크릿을 넣으면 공증까지 처리됩니다.

Windows 포터블은 WebView2 런타임이 시스템에 있어야 합니다. Windows 11에는 기본 포함이고 Windows 10도 대부분 Edge와 함께 들어와 있지만, 없는 환경이 걱정되면 설치본을 쓰거나 `webviewInstallMode` 를 `fixedRuntime` 으로 바꿔 런타임을 동봉하면 됩니다.

Linux ARM(aarch64)은 아직 없습니다. 크로스 컴파일보다 ARM 러너를 한 줄 추가하는 편이 낫습니다.

이식성 면에서 이 코드에는 플랫폼 분기가 없습니다. 경로 구분자는 양쪽을 모두 받고, CSP는 asset 프로토콜의 두 형태(`asset:` 와 `http://asset.localhost`)를 모두 허용하며, 글꼴 열거는 `fontdb` 가 OS별 디렉터리를 알아서 찾습니다.

## 의존성

프런트엔드와 Rust 모두 각 패키지의 **최신 버전**을 씁니다. 다만 하나는 최신이 아닙니다:

- **TypeScript는 6.x** 입니다. 7.x가 나와 있지만 `svelte-check` 최신판(4.7.6)이 `typescript: ^5 || ^6` 만 지원해서, 7로 올리면 `npm run check` 가 동작하지 않습니다. svelte-check이 7을 지원하면 함께 올리면 됩니다.

Vite 8은 번들러가 rollup에서 rolldown으로 바뀌었고 esbuild를 더 이상 동봉하지 않습니다. 그래서 `vite.config.ts` 는 미니파이어를 이름으로 지정하지 않고 불리언만 넘깁니다 — 이름을 박아 두면 릴리스마다 따라가야 합니다.

취약점 점검:

```bash
npm audit
cd src-tauri && cargo audit     # cargo install cargo-audit
```

작성 시점 기준 양쪽 모두 **취약점 0건**입니다. `cargo audit` 이 남기는 19건은 전부 "미관리(unmaintained)" 또는 unsound 경고이고, 대부분 Tauri의 리눅스 백엔드가 쓰는 GTK3 바인딩이라 Windows 빌드에는 아예 컴파일되지 않습니다. 나머지(`unic-*`, `bincode`, `proc-macro-error`)도 전이 의존성이라 직접 손댈 수 없습니다.

직접 줄인 것은 하나입니다. syntect의 `yaml-load`·`plist-load` 기능을 껐습니다 — 내장 문법·테마 덤프만 쓰고 런타임에 `.sublime-syntax` 를 읽지 않으므로 필요 없고, 그 결과 미관리 크레이트 `yaml-rust` 가 컴파일 대상에서 빠집니다. `cargo audit` 은 Cargo.lock 을 훑기 때문에 경고 수는 그대로지만, 바이너리에는 들어가지 않습니다.

## 저장소에 들어가는 것

코드와 이 문서만 넣습니다. `.gitignore` 가 빼는 것들:

- `node_modules/`, `dist/`, `src-tauri/target/` — 설치·빌드 산출물
- `fixtures/` — `scripts/gen-fixtures.mjs` 가 만드는 검증용 데이터. `huge.json` 하나가 500MB 남짓이라 커밋하지 않고 필요할 때 다시 만듭니다
- `.claude/`, `.agent-works/`, `plans/` — 에이전트·계획 문서
- `.vscode/` — 편집기 설정

`.gitattributes` 는 줄바꿈을 LF로 고정합니다. 없으면 Windows에서 체크아웃할 때 전부 CRLF로 바뀌어, 다음 커밋에 트리 전체가 변경된 것으로 잡힙니다.

`package-lock.json` 과 `src-tauri/Cargo.lock` 은 **넣습니다**. 애플리케이션이라 빌드가 재현돼야 합니다.

## 알려진 한계

- JSON 파일은 4GB까지입니다 (오프셋이 `u32`).
- 검색은 리터럴 문자열이며, 대소문자 무시는 ASCII 범위에서만 동작합니다. 정규식과 JSONPath 표현식은 아직 없습니다 — 경로 검색은 `$.items[3].name` 같은 경로 문자열에 대한 부분 일치입니다.
- 마크다운 렌더링은 16MB까지입니다. 그보다 큰 파일은 열리지 않습니다.
- 펼침 깊이 프리셋은 9까지이며 기본값도 9입니다. 그보다 깊은 단계는 개별 노드를 펼쳐서 봅니다.
- 파일을 mmap 하므로, 열어 둔 파일이 밖에서 바뀌면 다시 열어야 합니다.
- 문서 편집·저장 기능은 없습니다. 읽기 전용 뷰어입니다.
